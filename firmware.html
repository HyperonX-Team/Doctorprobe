Firmware guide

Configure, compile, and flash the ESP32 firmware, then understand what it does on boot, on button press, and in calibration mode.

1. One-time toolchain setup

arduino-cli core update-index
arduino-cli core install esp32:esp32@2.0.14
arduino-cli lib install "Adafruit TCS34725" "DHT sensor library" "ArduinoJson"
LibraryVersion
Adafruit TCS34725latest
DHT sensor librarylatest
ArduinoJson^7

(Arduino IDE 2.x users: install the same via Library/Boards Manager.)

2. Configuration

cd arduino/doctordrobe
cp secrets.h.example secrets.h     # set DEVICE_API_KEY if the backend requires it

Edit config.h:

SettingExampleMeaning
WIFI_SSID / WIFI_PASS"my_wifi"Your 2.4 GHz network
BACKEND_HOST / BACKEND_PORT"192.168.1.100" / 8000API address
USE_HTTPSfalseTLS on/off (true behind a TLS proxy)
DEVICE_ID"doctordrobe_demo_001"Must match the Device ID in the app

secrets.h holds DEVICE_API_KEY (required when the backend sets DEVICE_API_KEY) and ROOT_CA_PEM (only for private CAs). It is git-ignored - never commit it.

3. Compile and upload

arduino-cli board list                        # find your COM port
arduino-cli compile --fqbn esp32:esp32:esp32 doctordrobe
arduino-cli upload -p COM3 --fqbn esp32:esp32:esp32 doctordrobe
# Linux/macOS: use /dev/ttyUSB0 instead of COM3

Expected result: ~60% of program storage. Arduino IDE 2.x: open arduino/doctordrobe/doctordrobe.ino, pick "ESP32 Dev Module" + port, click Upload.

4. Behaviour

Boot

  • Connects to Wi-Fi (retry every 5 s, up to 20 attempts).
  • Syncs NTP when USE_HTTPS is true - required for TLS validation.
  • Prints boot status to the serial monitor at 115200 baud.

Button press

  1. Reads the TCS34725 (RGB normalized against the clear channel) and the DHT22.
  2. POSTs {"device_id", "rgb_r", "rgb_g", "rgb_b", "temperature_c", "humidity_pct"} to /api/devices/reading.
  3. LED blinks 3× on HTTP 200/201; stays on 5 s on failure.
  4. Network drops trigger automatic reconnect with backoff.

5. Serial protocol

Open the Serial Monitor at 115200 baud:

CommandEffect
CAL glucose 2.5Arm calibration mode: the next button press is labeled glucose @ 2.5 and POSTed to /api/calibration/samples (averaging 10 reads).
CALCR / CALCLEARDisarm calibration mode without capturing.

The full calibration workflow (control standards, capture strategy, retrain) is on the calibration tutorial page.

6. HTTPS notes

  • With USE_HTTPS true, the device verifies the server certificate against the bundled root CA (NTP must have synced first).
  • For a LAN-only setup with a self-signed proxy cert, either install the CA in ROOT_CA_PEM or keep USE_HTTPS false.
