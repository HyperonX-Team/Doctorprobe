Security

The security model treats the browser and the device as separate trust domains, keeps secrets out of the database, and never trusts client-supplied identity.

Threat model

ThreatMitigation
Database leakedReports are Fernet-encrypted; passwords are PBKDF2 hashes; session tokens are SHA-256 digests.
Guessed user id / forged requestsNo endpoint accepts a user id; ownership always derives from the bearer token and is checked per request (403).
Credential stuffingPer-IP login rate limiting (429 beyond budget) + uniform 401s that don't reveal which field was wrong.
Timing attacks on the device keyhmac.compare_digest (constant-time) for X-API-Key.
Session theft from storageTokens are opaque and revocable; expiry default 30 days; password change revokes all other sessions.
Error details leaking internalsUnhandled exceptions log server-side and return a generic 500 envelope.

Encryption at rest

  • Reports: Fernet (AES-128-CBC + HMAC-SHA256), key derived via SHA-256 from FERNET_KEY.
  • Passwords: pbkdf2_hmac, per-user random salt, 260k iterations.
  • Sessions: only the SHA-256 digest of each token is stored.

Production must-change

The default FERNET_KEY is dev-key-change-me. Generate a strong value and inject it via your secret store: 

python -c "import secrets; print(secrets.token_urlsafe(48))"

Device API keys

Device ingest endpoints (/api/devices/reading, /api/devices/baseline, /api/calibration/samples) require the X-API-Key header when DEVICE_API_KEY is set. When unset (local development), the check is skipped. The firmware keeps its copy in the git-ignored secrets.h.

CORS

Allowed origins come from the CORS_ORIGINS environment variable - never a hardcoded list. Restrict it to your real origin(s) in production.

Request hygiene

  • Every endpoint validates input via Pydantic v2: bounds, enums, lengths. RGB 0-255, humidity 0-100 %, temperature −40-85 °C.
  • Constant-time comparisons for both the device key and (via hashing) session lookups.
  • Structured JSON logs with request ids for auditability; secrets are never logged.

Production checklist

  1. Generate and inject a real FERNET_KEY via the secret store.
  2. Set DEVICE_API_KEY and mirror it in the firmware's secrets.h.
  3. Restrict CORS_ORIGINS to the real frontend origin.
  4. Terminate TLS at a reverse proxy; enable USE_HTTPS in the firmware (NTP + trust bundle).
  5. Use PostgreSQL, not SQLite; back up the volume; run migrations as a deploy step.
  6. Add per-device API keys with rotation and a device registry (documented next step - today a single shared key is used).

Known gaps

Password recovery and email verification are not implemented; the login limiter is per-process (not distributed); the calibration read endpoints are unauthenticated by design for the local workflow. All three are tracked as roadmap items.
