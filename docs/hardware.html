Hardware build guide

How to buy the parts, wire them up, and get a working Doctordrobe device on your desk - about an evening's work and $35-45 of parts. No soldering needed on a breadboard.

1. Parts list (BOM)

103D-printed or plastic enclosure (optional)1Housing$10-20

Budget total: ~$35-45. Cheapest viable: ESP32 + TCS34725 + button on a breadboard (~$15).

Alternatives

Any I2C colour sensor with a library (e.g. APDS-9960) can replace the TCS34725 - the firmware targets its API. DHT11 works for demos (less accurate). The ESP32's onboard blue LED on GPIO2 means you can skip part #5.

2. Tools

  • Screwdriver (small) - only if you use the enclosure
  • Soldering iron + solder - only for permanent/perfboard assembly
  • A computer with Arduino IDE 2.x or arduino-cli
  • Multimeter (optional, for continuity checks)

Two gotchas

GPIO0 doubles as the flash-mode strapping pin - don't hold the button while flashing. If using a bare DHT22 (not the module), add a 10 kΩ pull-up between DATA and 3V3.

4. Assembly steps

  1. Breadboard layout. Place the ESP32 at the edge so the micro-USB port hangs off the side.
  2. Power rails. Run 3V3 and GND rails the length of the board.
  3. I2C bus. Wire SDA→GPIO21, SCL→GPIO22, and power to the TCS34725.
  4. DHT22. Wire DATA→GPIO4, power, ground.
  5. Button. One leg to GPIO0, the other to GND.
  6. LED. Anode to GPIO2 through the 220 Ω resistor; cathode to GND.
  7. Visual check. Walk the wiring table line by line before applying power. Continuity mode catches swapped SDA/SCL.
  8. Power up. Connect USB - the LED should stay off until the button is pressed.

5. First power-on test

Open the Serial Monitor at 115200 baud (or arduino-cli monitor -p COM3 -c 115200): 

[boot] Doctordrobe firmware 1.0.0
[sensor] TCS34725 found
[wifi] connected, IP: 192.168.1.45

TCS34725 not found → check I2C wiring. Wi-Fi never connecting → re-check config.h credentials (and remember: 2.4 GHz only).

6. Using the device

  1. Start the backend (docker compose up --build or local uvicorn).
  2. In the app, verify the Device ID matches DEVICE_ID in config.h (Settings page).
  3. Place a saliva strip under the TCS34725.
  4. Press the button - the firmware POSTs to /api/devices/reading.
  5. LED blinks 3× → accepted. App → Checkup → Scan with Device.
  6. LED stays on 5 s → failure. Check backend logs, BACKEND_HOST reachability, Wi-Fi, and X-API-Key if enabled.

7. Troubleshooting hardware

SymptomCause / fix
No serial outputWrong baud, charge-only cable, board in flash mode (unplug/replug)
TCS34725 not foundSDA/SCL swapped; module not powered; loose jumper
Wi-Fi never connectsWrong SSID/pass; ESP32 cannot see 5 GHz networks
LED stays on 5 s after pressBackend unreachable: host IP/port, firewall, DEVICE_API_KEY mismatch
Button does nothingButton legs swapped or not to GND; check GPIO0 with a multimeter
Reading identical every timeNormal - the analysis is deterministic per reading; check the serial log for fresh sensor values
DHT read fails (isnan)Check DATA pin + pull-up; DHT22 needs ≥2 s between reads (firmware handles it)

8. Enclosure (optional)

  • 3D-print a box (~100×60×30 mm): sensor-window hole flush with the top so strips slide under, button cutout, micro-USB notch.
  • Keep the sensor window clean; test strips sit flat on the glass.
  • A thin frosted-plastic diffuser over the sensor improves reading consistency.
