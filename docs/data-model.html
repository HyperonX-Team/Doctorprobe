Data model

Six tables under SQLAlchemy 2.0 (async), versioned by Alembic. The crown jewel - the full biomarker report - is stored encrypted; only a plain summary, risk label, and quality grade are readable for list views.

Relationships & cascade rules

ParentChildOn delete
userssessions, checkupscascade - deleting an account removes everything
checkupsshare_eventscascade; the unique checkup_id makes sharing idempotent

Encryption at rest

checkups.encrypted_data holds the full report JSON encrypted with Fernet (AES-128-CBC + HMAC). The key is derived with SHA-256 from FERNET_KEY - so a single secret protects every report, and the columns that stay plain (summary, risk, grade) are deliberately the ones that leak nothing medically sensitive.

Rotate responsibly

Changing FERNET_KEY without re-encrypting stored reports makes them undecryptable. For production, plan a key-rotation job or use a KMS.

Identity columns

  • All primary keys are UUIDv4 generated in the application.
  • users.email is unique + indexed (case-normalized).
  • sessions.token_hash is unique + indexed; sessions.user_id is indexed.
  • checkups.user_id, device_readings.device_id, and calibration_samples.analyte are indexed for the hot query paths.

cd backend
alembic upgrade head
alembic downgrade base   # and back up, to sanity-check a change
alembic revision --autogenerate -m "describe the change"

SQLite quirk

SQLite stores naive datetimes; the code treats them as UTC on read (_as_aware helpers). PostgreSQL keeps full timezone information.
