Getting started

Run the whole stack on your machine, create an account, and take your first checkup — no hardware required for the software path.

Prerequisites

ToolVersionUsed for
Python3.11+Backend (FastAPI, pytest)
Node.js + npm20.xFrontend (Vite, Vitest)
Docker + Docker ComposelatestFull-stack run (optional)
arduino-cli or Arduino IDE1.x / 2.xFirmware (optional)

Option A — Docker Compose (fastest)

The Compose stack starts PostgreSQL, runs Alembic migrations automatically, and serves the SPA through Nginx: 

cp .env.example .env      # then edit FERNET_KEY / DEVICE_API_KEY
docker compose -f infra/docker-compose.yml up --build
  • Frontend: http://localhost
  • Backend API + OpenAPI docs: http://localhost:8000/docs
  • Health checks: http://localhost/health and http://localhost:8000/health

Option B — local development

Backend

cd backend
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
cp .env.example .env
alembic upgrade head
uvicorn app.main:app --reload --port 8000

Frontend

cd frontend
npm install
npm run dev       # http://localhost:5173

Add http://localhost:5173 to CORS_ORIGINS in the backend .env if the browser blocks requests.

Create an account

Open the app and click Create an account. Registration asks for an email, a password (min 8 characters), and the profile fields the analysis adjusts for (age, sex, height, weight, activity level). The backend normalizes the email, hashes the password, and returns a bearer token that keeps you signed in.

Run your first checkup

Every checkup is derived from a real device reading — there is no simulated mode. With no physical device yet, use the API to post a reading, then create the checkup from the UI: 

# 1. Register (returns a token + user profile)
curl -X POST http://localhost:8000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"you@example.com","password":"correct-horse-9!",
       "age":34,"sex":"female","height_cm":165,"weight_kg":62,
       "activity_level":"moderate","device_id":"doctordrobe_demo_001"}'

# 2. Post a device reading (no auth needed when DEVICE_API_KEY is unset)
curl -X POST http://localhost:8000/api/devices/reading \
  -H "Content-Type: application/json" \
  -d '{"device_id":"doctordrobe_demo_001","rgb_r":120,"rgb_g":200,
       "rgb_b":60,"temperature_c":24.5,"humidity_pct":45}'

# 3. Create the checkup with your token
curl -X POST http://localhost:8000/api/checkups \
  -H "Authorization: Bearer $TOKEN"

Back in the browser, the Checkup page will pick up the reading with Scan with Device and navigate you to the report.

No reading yet?

If the device has never reported, POST /api/checkups returns 409. Press the device button first, or post a reading as above.

What next?

  • Build the physical device — full BOM and wiring.
  • Calibrate the sensor model — replace simulated data with real samples.
  • Browse the API reference — every endpoint.
