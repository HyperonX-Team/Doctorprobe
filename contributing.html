Contributing

The project is small, honest, and test-first. If you want to help, the highest-value work is real calibration data and the biology in the forward model - not more UI chrome.

Development setup

# Backend
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
alembic upgrade head
uvicorn app.main:app --reload --port 8000

# Frontend (separate terminal)
cd frontend
npm install
npm run dev

Conventions

  • Determinism is sacred. The analyzer must produce the same report for the same input - no randomness, no simulated readings.
  • Ownership from the token. New endpoints derive the user from get_current_user; never accept a client-supplied id.
  • Tests are in-memory. Backend tests use in-memory SQLite via pytest-asyncio; frontend tests mock fetch with URL-aware shapes.
  • Types mirror the backend. Frontend types in src/types/index.ts must stay in sync with the Pydantic schemas.
  • Docs live with the code. This site (in docs/) and the READMEs should be updated with behaviour changes.

Where to help

Highest value

  • Real calibration data. The single biggest lever: collect labeled samples per the calibration tutorial and publish them (or a derived dataset) so the model can be trained on reality.
  • Better biology in the forward model. Improve generate_synthetic_data.py: more realistic pad cross-talk, pH buffering, temperature kinetics, strip-batch variance.
  • Clinical validation partnerships. A lab that will co-measure saliva panels against reference assays.

Engineering

  • Per-device API keys with rotation + a device registry.
  • Password recovery and email verification (see auth roadmap).
  • Distributed login rate limiting (Redis).
  • Trend alert push notifications.
  • Quality-weighted trend series that down-weight poor captures.
  • Session-management UI (list + revoke sessions in Settings).

Good first PR

Pick something from the Engineering list above, add the failing test first, then the implementation. The test suites are the specification.
