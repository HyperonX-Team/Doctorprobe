Clinician PDF export

A print-ready A4 document of any checkup - the thing a user can hand to a clinician. It carries the results, the measurement-quality verdict, and a 30-day trends appendix, with the same "not a medical device" disclaimer as the app.

Getting the PDF

  • In the app - open any report and click Download clinician PDF.
  • Via API - GET /api/checkups/{id}/export with the bearer token; returns application/pdf with a Content-Disposition: attachment header. 
curl -OJ http://localhost:8000/api/checkups/$CHECKUP_ID/export \
  -H "Authorization: Bearer $TOKEN"

Ownership is enforced exactly like the JSON endpoints - another user's checkup returns 403, no token returns 401.

What the document contains

SectionContents
HeaderDoctordrobe Biomarker Report · home health analysis · the disclaimer
PatientAge/sex, height/weight, BMI, activity level, device id
ResultAnalysis date, overall risk, the plain-language summary, and the measurement-quality verdict with reasons
BiomarkersTable: name, value + unit, reference range, state, identifiability confidence
Analysis methodSolver, prior source (SaliNet vs Beer-Lambert), snapshot count, reconstruction residual, condition number
Trends appendixPer-marker series summary over the last 30 days (count, latest, mean, min/max) plus any fired alerts

How a clinician should read it

  • Measurement quality first. A poor capture is flagged with reasons and a retake recommendation - treat its numbers as unusable.
  • Confidence column. Values with low identifiability were not resolvable from the measurement; they carry a caveat in the JSON report and a low percentage in the PDF.
  • Trends appendix. Context: a single high value surrounded by a stable baseline reads differently than three consecutive rises. The appendix includes the alerts the system derived.
  • Analysis method. Transparency about how the numbers were produced - including that the prior may be synthetic until the user calibrates.

Implementation notes

  • Built with fpdf2 (pure Python, no system PDF dependencies - fits the slim backend image).
  • Uses built-in core fonts; non-Latin-1 characters (µ, -, →) are normalized to ASCII so the document renders identically everywhere.
  • The trends appendix reuses the same build_trends service as the Trends page, so the PDF and the UI never disagree.

Not for diagnosis

The document is designed to be informative and honest, not clinically validated. It states its own limitations - including that the model may be trained on simulated data - so a clinician can weigh it accordingly.
